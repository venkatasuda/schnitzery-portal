# Pruning audit — 11 Nov 2026

Static scan of `src/` (import graph, export usage, route links, CSS class usage). Nothing was deleted. Counts come from scripts over the source, so a dynamic reference (a class built from a string, a URL stored in a database row) can make an item look unused when it is not; each delete below says what to check first.

Two corrections to the brief: the app does not use Tailwind classes (styling is plain CSS in `globals.css`), and builds run on webpack (`next build --webpack`), not Turbopack.

## 1. Duplication

### 1.1 UI copy-paste

The same three style objects are pasted at the bottom of 13 pages, each a hand-written version of classes that already exist (`.card`, `.form-input`, `.btn-gold`):

`announcements/page.tsx:142-144`, `incidents/page.tsx:122-124`, `noshow/page.tsx:129-131`, `profile/page.tsx:164-165`, `leave/page.tsx:156-157`, `notes/page.tsx:102-103`, `settings/page.tsx:98-99`, `checklist-status/page.tsx:139-140`, `attendance/corrections/page.tsx:216`, `audit/page.tsx:57`, `directory/page.tsx:67`, `labor/LaborClient.tsx:233`, `kiosks/page.tsx:104`, plus `inputStyle` in `login/loginForm.tsx:163`, `change-password/ChangePasswordForm.tsx:176`, `ProfileSettings.tsx:158`.

`fmtDate` is redefined in 10 files. `export/page.tsx:19` calls `toLocaleDateString()` with no locale and no time zone, so the payroll export page formats dates by the browser's settings while every other page uses the app locale and Europe/Berlin.

### 1.2 Data layer

**Caller context, 35 copies.** `admin.ts:13`, `cover.ts:14`, `schedule.ts:30`, `leave.ts:25` and 31 more each define a private `getMe()` (or `ctx` / `scope`) with the same body: create client, `auth.getUser()`, read `users`, resolve the active branch. The ones I compared are byte-identical. Beyond the duplication, every server action pays those round trips again; a page that calls three loaders does the auth and profile lookup three times.

**Role checks.** `["manager","branch_owner","brand_owner","super_admin"]` appears 58 times; `isManagerRole` already exists in `lib/auth/rank.ts`.

**Admin client.** `createAdminClient(url, key, …)` is built inline in 18 places.

**Analytics loaders.** `branch-analytics.ts` (492 lines), `ops-dashboard.ts`, `org-overview.ts` and `shift-conflicts.ts` each carry their own `mondayOfDate`, `dayNameOf` and their own join of roster against attendance. `queries/analytics.ts` (77 lines, `getAnalytics`) is imported by nothing.

**Typed client unused.** `lib/database.types.ts` (2,290 lines) is imported by nothing; queries cast to `any` instead.

## 3. Business logic

### 3.1 Dates

"Today" is consolidated: everything calls `berlinToday()`. Eight files wrap it in a pointless local `todayStr()` (`admin.ts:24`, `inventory.ts:36`, `operations.ts:30`, `owner.ts:28`, `live-attendance.ts:30`, `ops-dashboard.ts:34`, `org-overview.ts:19`, `shift-conflicts.ts:39`).

Week start is not:

| Where | Method |
|---|---|
| `lib/time/berlinDate.ts:55` | Canonical `mondayOfDate` (noon UTC anchor) |
| `branch-analytics.ts:38`, `ops-dashboard.ts:22`, `org-overview.ts:20`, `shift-conflicts.ts:28` | Four identical private copies (midnight UTC anchor; same result for date strings) |
| `leave.ts:76`, `PrepHistory.tsx:12` | Inline `(getUTCDay()+6)%7` arithmetic |
| `schedule/compare/page.tsx:13` | **Uses the device's local clock** (`new Date()`, `getDay()`), not Berlin. A manager whose device is in another time zone, or anyone around midnight, can get a different week than the server |

`addDays` exists 10 times (`kiosks/page.tsx`, `schedule/page.tsx`, `RosterLabourPanel.tsx`, `prep-list.ts`, `cover.ts`, `leave.ts`, `owner-insights.ts`, `reconciliation.ts`, `shift-conflicts.ts`, `tips.ts`).

Target: `berlinDate.ts` exports `berlinToday`, `mondayOfDate`, `addDays`, `dayNameOf`; nothing else in `src/` does date arithmetic on `Date` objects. Add a check to `scripts/checks/business-date.cjs` that fails on a local `function mondayOf` / `addDays`.

### 3.2 State

`roster/page.tsx` holds about 25 `useState` values in one component, including three copies of the roster (`roster`, `savedRoster`, `expected.draft`) that must be kept in step by hand at lines 70, 195 and after publish. One `useReducer` with `{loaded, working, expected}` removes the manual syncing; "dirty" becomes `working !== loaded`.

I did not find deep prop-drilling chains elsewhere: most pages are single components that call server actions directly. The fragmentation is the opposite problem, one large component per page, with the roster editor (437 lines) as the main case.

### Consolidate

1. **`lib/auth/session.ts`**: one `getMe()` wrapped in React `cache()` so auth and profile are read once per request; export `isManager` from `rank.ts`. Replace the 35 copies and 58 role literals file by file (mechanical; `payroll-access.cjs` and `multi-branch-access.cjs` guard behaviour).
2. **`lib/supabase/admin.ts`**: one `adminClient()`; replace 18 inline constructions.
3. **`lib/time/berlinDate.ts`**: add `addDays`, `dayNameOf`; delete the 5 + 10 + 3 copies; fix `schedule/compare/page.tsx:13` to use `mondayOfDate(berlinToday(), offset)`.
4. **`lib/format.ts`**: `eur`, `fmtMins`, `fmtDate` (app locale, Europe/Berlin). Replace 24 + 8 + 10 definitions; this also fixes `export/page.tsx:19`.
5. **Style objects**: in the 13 pages, swap `style={card}` / `style={input}` / `style={primaryBtn}` for `.card`, `.form-input`, `.btn-gold` and delete the constants. Do this together with the button-token work from the first audit.
6. **Roster state**: `useReducer` in `roster/page.tsx`, done with the 7-column grid refactor.
7. **Typed client**: either wire `database.types.ts` into `createClient<Database>()` and remove the `as any` casts over time, or delete the file. Wiring it is the better use; it turns column typos into build errors.
8. **Analytics**: after the page-view check, merge `conflicts` + `noshow`, and pick one of `overview` / `summary` / `analytics` as the performance page.

Order: 1–4 are safe mechanical changes with tests already around them and should go first; 5–6 ride along with Phase 1 and 2 of the first audit; 7–8 need a decision from you.
