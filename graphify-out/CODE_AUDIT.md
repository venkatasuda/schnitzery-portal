**Historical findings:** local repairs and their rollout status are documented in `docs/BUGFIXES.md` (2026-10-11). The findings below describe the audited snapshot, not a claim that the repaired paths still contain these defects.

The app needs consistent business rules and transaction boundaries before another visual redesign. Four defects were reproduced against the actual source using mocked services. Other findings below are source-confirmed paths or explicitly conditional risks, not claims about the live database.

## Important gaps and conditional risks

- **Inventory movement accounting:** receiving deliveries, waste logs and transfers are separate records rather than an integrated movement ledger. Usage inference includes count differences and purchases but does not reconcile transfers; a stock transfer can appear as unexplained consumption. Use counts as reconciliation snapshots and a movement ledger for receipts, consumption, waste, adjustments and transfers. Keep sales consumption and waste separate to avoid double counting.
- **Unbounded reads:** several inventory/owner/AI queries have no pagination. Supabase row caps can truncate history as data grows. Fetch latest counts server-side, aggregate reports in SQL, and paginate history; verify configured limits rather than assuming the full table is returned.
- **Historical payroll:** approved runs store approval metadata, not calculated rows or a wage snapshot. Recalculation uses current wages. Decide and implement effective-dated wage records and immutable approved results so old payroll does not change after an edit.
- **Approval status:** payroll reads completed logs without filtering `approval_status`. Establish whether unapproved attendance is payable; enforce the chosen rule consistently.
- **Franchise isolation:** service-role reads in owner waste and transfer branches are broad. Role checks are not an organization filter. Current documentation treats brand owner as global. If unrelated franchises share this deployment, explicit organization scope is required on all service-role paths and database policies.
- **Privacy and credentials:** contact-email database exposure is explicitly accepted in the pending privacy decision; removing it from the directory does not prevent direct same-branch database reads. Wage migration and credential rotation status conflict across documents. Verify deployed schema/account state without printing secrets before treating these as resolved.
- **Database reproducibility:** `schema/production-*.sql` contain duplicated snapshot DDL and pending fixes have conflicting status notes. They are not a trustworthy ordered migration history. Establish a verified baseline and timestamped migrations, then test a fresh database restore.
- **AI reality:** this repository contains a direct Anthropic SDK chat endpoint with three read tools (stock, expiry, waste), six-step cap and a feature flag. It does not contain LangChain, Langfuse, a nightly proposer or an evaluation harness. Runtime input validation, request/token budgets, throttling and per-branch/source-date outputs should precede autonomous writes. Cross-branch tools currently omit branch identity from returned items and waste aggregates omit units, making some owner comparisons ambiguous.
- **Offline attendance:** malformed events are filtered and can remain indefinitely queued. Verify reject/quarantine UX and database replay rules with real offline sequences, duplicate delivery, session switching and database failure tests.
- **Tests/CI:** current unit tests focus on date, rank and wage helpers. They did not catch the reproduced endpoint/payroll defects. Lint and dependency audit are advisory. Add focused authorization, exact-pay, transaction failure and concurrent-action regression checks before broad snapshot testing.

## Improvement order

1. **Security:** close A01/A02; centralize role and branch rules using existing auth helpers; verify live RLS and service-role scope.
2. **Business accuracy:** one paid-minute/pay calculation; deterministic stock queries; stable product IDs; validation; precise metric names and missing-data states.
3. **Reliability:** atomic approval/transfer/discard operations, optimistic roster versioning, idempotent retries, approved payroll snapshots and reproducible migrations.
4. **UI/UX:** retain desktop management and employee task views. Give each domain one workspace; distinguish summary, action and history. Use one toolbar per table, aligned numeric columns, clear status/freshness, useful error recovery and consistent dialogs. Verify actual role flows and responsive widths rather than declaring visual quality from source alone.
5. **Business intelligence/AI:** add reliable sales/recipe consumption inputs and reconciled waste valuation, then read-only explanations with evidence. Add scheduled proposals and explicit approval only after the underlying calculations and permission paths are tested.
